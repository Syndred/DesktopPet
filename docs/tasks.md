# 灵境实施任务

更新于 2026-10-25。当前需求与分工以 [并行实施约定](implementation/parallel-plan.txt) 和用户批准的设计为准。

当前交付顺序：

1. 统一 managed Auth、owner/device/SID、RLS 与事务内权限校验，保留旧账号本地验证和原档归属。
2. 以 PostgreSQL CAS、幂等回执和服务端规则完成伙伴、探索、领地、经济及联机；资源使用私有 Storage 和受验证引用。
3. 双端自动同步同时保证真实读回、原请求恢复、冲突保护和凭据不进入云端存档。
4. 协调方独立复核真实运行、严格集成回归、冻结源码打包，并验收实际 EXE。
5. 依照消费者与恢复快照删除已替代旧代码和旧内容，保留必要的原档读取、用户资源、历史数据和设计源文件。

具体状态、已知边界和证据集中在 [当前进度](task-progress.md) 与 [交付要求](project-delivery-tasks.md)。本文件不再维护已经退役的原型编号、伪服务任务或旧部署命令。
