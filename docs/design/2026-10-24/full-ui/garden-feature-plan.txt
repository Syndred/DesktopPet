灵境：领地菜园与喂养闭环
2026-10-24（Asia/Shanghai）
状态：设计方案，未实施运行时代码、数据库变更或云端部署。

一、玩法闭环

探索 / 对战 → 获得种子 → 基础菜园种植 → 成熟 → 收获进入背包
背包里的胡萝卜 / 莓果 → 选择一只伙伴 → 喂食 → 饱食与亲密度提升
背包里的稻米 → 制作米饭 → 选择一只伙伴 → 喂食
伙伴养成 → 继续探索 / 对战 / 驻守 → 获得种子与领地加成

三、首版规则建议

1. 每个账号都有基础菜园，首次赠送少量种子。探索与对战是后续种子来源。
2. 菜园位于“领地”功能内，但基础种植能力不依赖赢得 PvP 或占有真实地理区域。
3. 基础菜园和已收获物品属于账号；领地易主不删除地块进度与背包物品。
4. 领地可提供额外收成或扩展地块加成；数值独立配置，保留原有区域捕捉收益规则。
5. 首版作物：胡萝卜、番茄、莓果、稻米。胡萝卜、番茄、莓果可作为虚拟宠物食物；稻米先制作米饭。
6. 首版提供一个简单配方：稻米 ×1 → 米饭 ×1。时间、产量与食物效果均是待平衡配置，不以设计图示例数值锁定。
7. 作物可离线生长，成熟后等待收获；首版不因玩家离线而枯死，也不加入偷菜、强制打卡或付费催熟。
8. 喂食只影响当前指定 petId，扣除该账号库存；其他同形象伙伴不受影响。
9. 生长阶段是状态，不是大量常驻计时器。持久化 plantedAt / maturesAt，界面按当前时间计算展示。
10. 联机场景以服务端时间和库存结算为准。客户端倒计时不构成发放奖励的依据。

四、数据职责建议

账号：garden 与基础地块归属、种子和物品库存。
地块：plotId、ownerAccountId、cropType、阶段、播种时间、成熟时间、版本号。
配方：recipeId、输入 itemId / quantity、输出 itemId / quantity。
操作记录：播种、收获、制作、喂养均带唯一 actionId 和版本号。
宠物：petId、所属账号、饱食、心情、亲密度；不能从相同模板 ID 推断操作对象。
事务：收获与发物品、制作时扣原料与加成品、喂食时扣食物与改宠物状态均原子提交。
防重复：相同 actionId 重试不重复发奖；同一成熟地块不能被两个设备重复收获。
同步：先复用既有账号与 Supabase 链路。SQLite 本地记录和云端记录的身份映射、离线重试与冲突处理需要实际实现。

五、验证闭环时的最小验收

可从种子播种到成熟收获，入库只发生一次；重启后生长进度恢复。
可消耗稻米制作米饭，库存前后数量正确。
给鱼丸喂一份米饭，只消耗一份并只更新鱼丸；小蓝与饭团保持各自状态。
重复点击、断网重试和双设备收获不能增加重复库存或产生负库存。
领地易主后基础菜园、在种作物和已经入库的物品仍可访问。
作物绘制、地图覆盖和桌宠动画不会抢占全局窗口焦点。
