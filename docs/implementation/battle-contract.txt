Main-process-only battle service (services.get('battle'))
beginWildChallenge({ownerAccountId,petId,actionId,challenge:{id,opponent:{petId,petName,element,level?,resourceRef?},...provenance}})
beginTerritoryChallenge(same input, challenge.territoryId recommended)
getOutcome({ownerAccountId,sessionId}) -> {session,won,settled}
settleTerritoryChallenge({ownerAccountId,sessionId}) -> {session,won,settled,receipt}
The challenge provider validates location, spawn, defender and ownership first. Renderer cannot inject a challenge or opponent.
Wild/territory sessions currently execute the retained local BattleRuntimeService, labelled authority:'local'.
Do not represent these as authoritative remote PvP; remote territory PvP must join a Supabase room.
Discovery's RegisteredWildBattleAdapter can use the provided methods and the act/leave commands directly.
The returned session.snapshot and every session.rounds[n].state contain actual HP, anger, statuses and free dodge.

Companions adapters (same synchronous shared SQLite connection)
getPet(owner,petId), listPets(owner), getSelections(owner), select(owner,{petId,slot:'battlePetId',actionId})
applyGrowthInTransaction(owner,{petId,actionId,effect:{experience,wins}})
Battle uses exactly the existing win=20 XP / loss=5 XP and 100 XP level rule supplied by companions.
An optional awardBattleResult(input) is also supported. No parallel inventory or pet state is maintained by battle.

Garden adapter
grantSeeds({ownerAccountId},{actionId,receiptId,source:'battle'},verifiedReceipt)
Called once for a completed win, in the same transaction as XP, report and battle reward receipt.
verifiedReceipt={ownerAccountId,id:session.id,source:'battle',eligible:true}; garden owns seed type and quantity.
If garden registers later, retrySettlement safely delivers the still-unclaimed seed receipt.
Territory ownership writes remain garden's responsibility; consume settleTerritoryChallenge's trusted receipt.

Resources adapter
Battle resolves the same resourceId via resources.resolve, context:'battle'; it stores no duplicate model library.
When the resources UI is present it uses that module's ResourceStage for both 2D and 3D, via a build-time optional glob.
The retained model-viewer renderer supports the standalone module before full integration.
