## 分工及接口边界

### 08 accounts：账号权限与双客户端存档

负责统一 Supabase Auth/JWT 与旧 runtime 文本 owner ID 的可靠映射、现有账号迁移/恢复、登录退出会话与设备语义、RLS 共用身份契约、完整存档 CAS/幂等/冲突与断网恢复。优先复用 supabase-js/Auth/安全存储，不另造认证系统。不盲目把 owner 改成 UUID，不重置既有密码或覆盖不同账号数据。新设备只能采纳经验证的对应云存档。

尽早提交供其他模块读取的共享身份/函数包装契约（建议 `infra/supabase/functions/_shared/lingjing-auth.ts` 或等价入口），包括 Auth UID→旧 owner 映射、服务端身份验证、actor context、错误与权限。共用身份迁移由08独占。联机允许同账号不同设备同步；同一账号不能伪装成两个对战玩家。双设备互踢语义需要与本轮需求统一，不能照搬旧的单 session_token 规则导致同步无法使用。

### 05 garden：云端领地与菜园经济

补全真实领地查询、争夺、胜负确认、驻守与归属变更，消除 `CLOUD_TERRITORY_UNAVAILABLE` 未实现路径。优先 PostGIS、PostgreSQL 行锁/事务/RPC；接同一账号身份、同一伙伴和库存，actionId幂等、expected revision和服务端时钟。领地易主不能清空基础菜园或个人背包。验证并发争夺、重复结算、断网后读回、胜负权限及跨账号拒绝。不得改04战斗UI；通过已有战斗上下文接口接入。提交自己的 territory/garden 函数和规范迁移。

### 03 discovery：云端探索捕捉及定位

把发现、准入、野外回合、捕捉凭证接入统一云身份及服务端权威，保留真实定位、精度门槛和显式模拟标记。跨客户端读回同一宠物和奖励，防重放、防伪造定位/胜利。与05对齐地理/领地接口；不另造战场。系统实地精度不足时如实记录，继续完成可验证的真实云端链路。

### 02 companions：实例数据保留与跨端一致

补齐在新身份映射和云存档下的宠物实例迁移、独立选择、成长、桌面位置及背包原子联动；验证同模板多实例在客户端A/B间保持原petId、名字和历史。接08的同步适配；不另建账号库、云库存或奖励通道。提供旧兼容代码的实际依赖清单与可删除候选。

### 07 resources：资源同步与2D清理

补齐受权限控制的 Supabase Storage 资源包上传/下载、manifest/hash/owner校验、断网恢复和新设备可用；本地内置资源继续可离线使用。优先官方Storage SDK及现有zip/图集能力；不上传第三方密钥。仅清理自己范围确认废弃的3D运行/导入代码，保留用户历史文件与资源迁移读取；提供清理和恢复证据。

### 06 conversations：聊天跨端与密钥边界

补齐聊天/人设/记忆在统一账号完整存档下的同步、稳定消息ID/顺序、并发及冲突恢复；保持单petId隔离和密钥主进程安全存储。个人BYOK密钥不因跨端存档进入云端或日志。复用assistant-ui/AI SDK，不引入第二套聊天传输。移除自己范围的废弃旧聊天实现，并验证恢复历史。
