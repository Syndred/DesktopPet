## 架构边界与参考

业务读写路径：桌面界面 → 账号鉴权后的业务 API → 云端事务及数据库 → 匹配的回执 → 更新本地显示缓存。实时事件通知客户端重新读取相关模块；重连后再核对云端。

| 数据 | 权威位置 | 本地职责 |
| --- | --- | --- |
| 宠物、成长、库存、对战、奖励、领地 | 云端 | 显示缓存；保存原请求 ID 和输入用于确认结果。不能靠本地改值决定扣除或奖励。 |
| 聊天、人设、记忆、连接公开配置 | 云端逐记录 | 显示缓存、待确认请求；旧内容先保全，有冲突时定位具体记录。 |
| 窗口位置、音量、桌面布局、设备偏好 | 本机 | 本机直接保存。 |
| 登录凭据、模型 API 密钥 | 本机安全存储 | 不进入业务同步或普通导出备份。 |
| 图片与动画、迁移前原档 | 本机缓存/保全档案 | 缓存可重新获取；原档保留，不自动覆盖云端。 |

因此“云端为唯一业务权威”并不要求本地磁盘零数据。正常使用自动交互；用户入口只需展示云端状态和可选刷新，不应要求手工上传/下载整份存档。

参考 [TanStack Query 缓存及重连刷新](https://tanstack.com/query/latest/docs/framework/react/guides/important-defaults)、[Supabase 数据变更通知](https://supabase.com/docs/guides/realtime/subscribing-to-database-changes)、[AWS 有限重试、退避与幂等](https://aws.amazon.com/builders-library/timeouts-retries-and-backoff-with-jitter/)。这些资料支持上述原则；本项目继续沿用现有 Electron/React/Pixi/Supabase，不为采用示例而更换技术栈。
