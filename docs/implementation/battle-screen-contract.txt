唯一战场契约 · 2026-10-24（统一战斗目标）

权威入口：runtime/services/battle-runtime.cjs。训练、好友、野外、领地均通过 battle feature
生成 BattleSession、提交 act、读取 snapshot，并由同一个 BattleScreen -> BattleArena 渲染。
packages/game-engine 的旧 TS 引擎不是桌面四模式的执行入口；差异与25对阵执行证据单独发布。

共享 React 入口：ui/src/features/battle/BattleScreen.tsx
<BattleScreen sessionId={实际战斗ID} returnTo={可选返回路由}/>
共用 hook：useBattleSession(sessionId)。页面不得自行调用 executeRound 或绘制另一套 HUD/四技能。
统一路由：/battle/session/:sessionId；训练/好友成功创建后进入该路由。
探索 EncounterView 只把 encounter.battle.battleId 交给 BattleScreen，不保留旧技能栏、HUD或规则 fallback。
领地挑战成功后进入其返回的确切 sessionId，不能依赖“最近一场”。

上下文结算：battle.context({sessionId}) -> {returnTo, action?, resultPath?, name?, settled?}。
battle.settleContext({sessionId,actionId,name?,showOnDesktop?}) 只转交已验证的 discovery.confirm 或
garden.territorySettle。共享结算区渲染收服/领地按钮；来源服务仍掌握定位/归属/库存/幂等。
普通战斗奖励和上下文结算分别有回执，不在 UI 自算伤害、经验、种子或领地归属。

动画与事件：BattleRound.visualEvents 由主进程从权威 round_result 生成。
阶段 windup -> release -> impact -> effects -> rest；分别表示起手、释放、命中/闪避、属性/治疗/持续伤害、
回归待机/胜利。ResourceStage 使用 attack_windup/attack_release/skill/hit/walk/idle/victory，
Motion 处理角色位移和真实数值反馈。HUD 只展示权威前态或后态，不重算中间伤害。
动画期间四技能锁定；应用关闭动画或 reduced motion 时立即采用最终权威状态，不播放动作。
恢复页面不重播旧回合；新回合（包括连续同技能）使用 sessionId+round 的独立序列。

QA 隔离：LINGJING_BATTLE_QA=unified-v1 且测试用户目录内存在匹配 marker 才可启用模拟 adapter。
仅接受 loopback endpoint、对应 run token 和 battle-qa- 合成账号。普通用户档不得启用。
模拟好友保留 OnlineDuelService 协议与同一内核，证据标 authority:simulated 与 scenarioId；
界面仅以小型场景图标和 tooltip 标识，不把模拟回执称作真实云端成功。

接口是本轮实现目标；完成状态及源码 SHA 以 status/battle.json 和自验 manifest 为准。
