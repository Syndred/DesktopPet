用户明确要求

统一好战斗界面，探索 PK 与普通对战直接复用一套；按已批准 UI 图还原，包括战斗动画。
各个属性都有角色，可验证属性克制与不同属性特性。
每个功能会话先自验；主会话逐一验收，有问题退回原会话修改并自己重验；全部收口后主会话最终验收。
云端能力可暂缓或用模拟数据测试，不作为本轮阻塞。
移除与玩家无关的说明、开发细节与冗余文字，尤其对战页；尽量使用图标、状态条、必要数值与按需提示。

当前独立检查确认的缺口

1. discovery/EncounterView.tsx 仍有独立 discovery-arena、HUD、回合区和 useEncounterPose；即使已局部复用 BattleMoves，仍未复用整套 battle/BattleArena，必须移除分叉呈现与动画控制。
2. 当前六角色只有水、火、金，缺木、土；不能仅凭角色数量判定属性覆盖完整。
3. 战斗页仍有标准生命说明、通用副标题、空记录解释与重复状态句；应转为简洁的视觉状态与 tooltip。
4. 单靠标题/间距、六模板及动作可解析的检查，不能证明四入口共享战场、动画正确或五行特性正确。

U01　唯一战斗呈现与控制器

训练、好友 PK、野外挑战、领地挑战只允许一个共享 BattleScreen/BattleArena、HUD、技能栏、回合记录、动画控制器。
入口提供 sessionId、mode、origin、returnTarget、opponent 与结算上下文；不拥有另一套技能按钮、动画或胜负计算。
野外收服、领地归属与训练/好友奖励使用共享结算区的上下文动作，保留各领域权威凭据和幂等。
批准 02-exploration-and-battle.png 下半作为共同视觉基准；背景主题可以随场景改变，不得形成另一套布局。

U02　五行角色与身份完整

金、木、水、火、土均有可选择、可出战的独立角色资源与明确元素标记；本轮补足木、土，原六角色保留。
正常 UI 不显示假角色名/默认替换图。领养、详情、地图、聊天、桌面、战场、战报都读取同一个 petId、resourceId 和元素。
沿用已建立的精确 Pixi 图集、统一近景构图、16 姿态帧/12 动作约定；新增资源必须经实际逐帧检查并保存来源/提示词。

U03　同一规则与五行特性

先查实际运行的权威规则入口，不照旧文档或 UI 示例猜测。
验证全部 25 种有序属性对阵、优势/劣势/中立、普通/属性/闪避/终结的交互，并逐一验证每元素真实特性、持续状态和回合变化。
UI 图标、提示、战报和动画事件解释同一份权威状态；不得为满足截图改变公式或另建探索规则 fallback。
旧未使用的规则实现必须明确退役或适配，不允许四个运行入口分别使用不同规则。

U04　共享完整动画

统一消费每个回合的事件序列，展示起手、攻击/技能释放、命中/受击/闪避、元素效果、状态/HP/怒气变化、回归待机。
同一行动连续发生也必须重新播放；恢复存档不能重复结算或错误重复播放历史行动。
尊重系统和应用动画开关；所有角色实际渲染均完整、不串格、脚底基线稳定。

U05　简洁且贴近图稿的战斗界面

统一字体、间距、卡片、头像近景、HUD 浅底与四技能卡，保留必要短技能名和关键数值。
移除开发实现说明、重复状态、冗余副标题、整段使用教程；将辅助规则、禁用原因与状态解释放入图标 tooltip 或按需详情。
必要确认、错误和重要结果仍须可理解。保留 aria-label、键盘焦点和可访问的禁用原因。
不以静态图覆盖界面、删除实际交互或只安装库来代替组件实现。

U06　隔离模拟与云端暂缓

可用明确的 QA profile/scenario 与模拟 adapter 验证好友、野外、领地的 UI/规则/状态闭环，不等待真实云恢复。

生产入口不自动切换为假云；QA 标识用紧凑图标/tooltip，诊断细节保留在证据中。
