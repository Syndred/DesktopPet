# Accounts integration

Current cloud contract: [cloud-identity-contract-2026-10-25.md](../../../../../../docs/implementation/cloud-identity-contract-2026-10-25.md). Isolated simulation contract: [QA_CONTRACT.md](QA_CONTRACT.md). A network failure never creates a local identity or enables simulation.

Accounts uses the shared SQLite connection and normal feature discovery. `getCurrentUser().id` / `ownerAccountId` remain the original storage owner TEXT. Supabase `authUserId`, per-profile `deviceId` and Auth `sessionId` are separate. Local accounts and verified legacy aliases retain their existing IDs; account-name matching never joins identities.

The default cloud path is `SupabaseRemote` -> deployed `lingjing-auth` / `lingjing-save`, using the committed public configuration or packaged public resource. Windows safeStorage encrypts opted-in access/refresh proofs; renderer results, ordinary login hints and cloud snapshots contain no Auth tokens. Auth checks actual managed sessions and the immutable revoked-SID ledger. Fresh password login on one device does not kick another device; local logout revokes only the selected device. A retired SID cannot return after another login replaces the device row.

Main-only business capability: `services.get('cloudActor').requireActor(expectedOwner?)` / `.invoke(functionName, body)`, or `accounts.requireCloudActor()` / `accounts.cloudInvoke()`. Published Resources name `cloudAuth` is an alias to the same object. Context exposes safe actor fields; SDK/client/invoke/accessToken/url/public key are non-enumerable and stay in main. One SDK per owner/device/SID reads current access tokens through its callback, including Realtime refresh; logout, invalidation and identity change remove channels. No consumer receives a refresh token. `requireRuntimeUser()` rejects the new Auth protocol, preventing JWTs from reaching legacy HTTP. The explicit legacy-auth escape hatch is transitional and is not the product default.

## Data preservation and cloud writes

Raw source files and content-addressed local legacy archives remain unchanged. Verified runtime owner IDs, pet IDs, history and names are preserved. Ambiguous global history stays `review-required`, without cloning data into accounts. `getLegacyInventory(owner)` returns only the verified owner's original data. The unavailable original server export is an external remaining item; empty target tables, synthetic QA or a preparation tool do not count as migration.

Shared adapters export/validate/restore synchronously under one SQLite transaction. `tables` claims prevent duplicated generic records. Verified older generic units can use `legacyTables/fromLegacyTables` through `backups.normalizeData(data,owner)` for restore/fingerprint comparison; the original envelope checksum and file never change. Credential-bearing tables and BYOK blobs are excluded from cloud content. User-authored message, memory and persona text remains byte-exact, including JSON examples.

Cloud CAS carries actionId, baseRevision and the full owner-bound envelope. Personal settings/chat may change; gameplay state must exactly retain the fragments constructed by trusted domain transactions. Domain workers call `lingjing_private.assert_service_actor(owner,uid,device,sid)` before protected work, then commit authority in the same transaction. It locks the canonical owner and actual Auth rows and checks anonymous, expiration, current device and immutable revocations without widening Auth table grants. Multi-owner transactions lock all owners in sorted order before domain rows.

A local snapshot is retained in `account_sync_sources`. Any cloud archive is a separately checksummed safe projection: raw legacy/source blobs and credential configuration are excluded and reported. It is never described as a complete copy of the original. Missing authority/privacy fields keep full-sync status incomplete. Prepared CAS input is retried unchanged after an uncertain response; only an exact receipt plus independent action readback becomes verified. A conflict retains the original outbox and does not force a new base.

Restore verifies owner, original checksum, schema, provenance and current-data fingerprint. Native dialogs own file paths. It writes a non-overwriting before-restore backup, then commits the complete unit or rolls back. Cloud preview/restore retains the server envelope and records its original revision/checksum with the normalized data fingerprint. Credentials/profile are never restored from a save. Async asset hydration is being integrated by Resources before the synchronous restore transaction.

## Desktop behavior and verification

Desktop settings use actual Electron topmost, hit-test forwarding, window-count, close-to-tray, foreground-fullscreen and native-notification APIs. Startup changes only on an explicit saved toggle. Privacy gates independently control real location and emotion collection; QA blocks real permissions, startup and native notifications. UI uses foundation controls/motion and Chinese account/settings routes.

`docs/implementation/status/cloud-accounts.json` and `docs/implementation/evidence/accounts/cloud-2026-10-25/` contain current source/run identities and scoped proof. Actual HTTPS covers Auth, immutable-session rejection, CAS concurrency/replay/readback, safe projections, original authored text and naturally expired signed JWTs. Two real Electron44 processes verified Windows encryption, independent same-account sessions, personal sync/conflict and durable restart recovery on one host. That partial run is explicitly not complete all-domain sync or two physical machines. Final all-domain native verification waits for current domain adapters/asset references; integration and release acceptance remain coordinated.
